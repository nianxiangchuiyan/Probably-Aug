# 变更记录与设计决策

## v0.1 — 概念草案（网页端对话）

**产出**：以"零号改造体"为主题的最初 Mod 构想。

**核心内容**
- 开局特质"零号改造体"，与原版"改造体危机"互斥；
- 新增改造体声望阵营；
- 玩家作为出逃改造体，需要电量维持身体；
- 植入物制造/销售/感染/报到；
- 夜间指令（拾荒、赚信用点、联络人脉、研究、抓捕、提供货物、世界事件）；
- 治安部追查（逃逸进度 + 警觉度）；
- 非特质玩家的"改造体之友"任务线与三种选择；
- 支配/革命两条结局方向。

**状态**：概念完整，但规则颗粒度不足以开发。

## v0.2 — 六条修订（网页端对话）

| # | 修订点 | 影响 |
|---|---|---|
| 1 | "接受改造"分支声望可 ≥100，并获得自身电量池；"不接受改造作为朋友"无法 ≥100 | 三类玩家差异化明确 |
| 2 | 补充声望 ≥20 阈值：每天额外 1 名改造体顾客（需存在隐藏改造体；有任务的不到店） | 声望低段有了正反馈 |
| 3 | 明确所有身份都可击杀改造体，获得信用点 + 治安部声望 + 额外降低警觉度 | 保留"改造猎人"玩法 |
| 4 | 新增高级违禁品"人类"、植入物过夜转化、夜间手术改造、手术工具特例 | 抓捕→改造闭环 |
| 5 | 新增玩家科技树（零号科研免费；接受改造可花钱/高阶需时间与活动；科研可免钱） | 成长线 |
| 6 | 成功改造按目标身份等级发放经费 | 网络经济闭环 |

**状态**：规则基本自洽，但仍是"策划草案"粒度：缺少状态机、公式、UI、数据模型、用例、技术可行性。

### 目标

把 v0.2 扩展成**可拆任务、可验收、可开发**的核心功能设计，同时明确把剧情/任务线/结局推迟。

### 新增内容

|---|---|

| 声望 | 获取/流失表、玩家类型硬上限、NPC 状态与网络容量 |

| 顾客 | 到店类型、破绽交互、≥20/60/80 效果 |
| 夜间指令 | 产出/警觉/失败表、世界事件数值接口、结算顺序 |

### 关键设计决策

| 编号 | 决策 | 理由 | 备注 |
|---|---|---|---|
| D-01 | 任务线只做状态门控，不写流程 | 用户明确剧情/任务线后续企划 | `QUEST` 状态即可 |
| D-02 | 声望 99/100 用"身份"而非"努力"区分 | 保持零号/接受改造的独占性 | FRIEND 封顶 99 |
| D-03 | 检测到植入物必报警 | v0.2 硬规则，制造风险 | 可选"首次预警"难度项 |
| D-04 | 感染是"夜间异步"而非"即时" | 强化"白天经营/夜晚经营"节奏 | 次日报到 |
| D-05 | 电量归零不阻止开店 | 防死锁，惩罚用 `DORMANT` + 警觉 | 连续 3 天强制救援 |
| D-06 | 击杀降警觉设每日递减 | 防"刷击杀压警觉" | 前 3 次全额 |
| D-07 | 失控改造体是负反馈来源 | 防止网络无脑滚雪球 | CONVERTED <100 时存在 |
| D-08 | 世界事件只定义数值/经济接口 | 叙事文本后续企划 | 先做供水/农场/停电 |
| D-09 | 自定义内容统一 `aug.` 前缀 | 降低 Mod 冲突 | 见 `03` §11 |
| D-10 | 科研与信用点二选一解锁 | 零号时间换强度，接受改造钱/时间换 | 先到先得 |
| D-11 | 不依赖 MelonLoader，改用官方 `ModLoader` + `ModHook` + `ModHelper` | 调研确认游戏自带 Mod 框架（Mono + 0Harmony） | 见 `04` |
| D-12 | 改造体声望**首选扩展原版派系栏**，回退 `ModData` + 自建面板 | 工坊有额外派系先例；官方无 `AddFaction`，需 Harmony/反射 | 最大架构风险 |
| D-13 | 保留 100 kJ 身体池，但充能器按原版 +3/晚 | 尊重用户设定；主要恢复靠电费/电池/转换器 | 量纲待校准 |
| D-14 | 夜间外出按原版：1 次/晚、三地点共用、次日 −1 | 不破坏原版限制 | 只影响当日闭店后 |
| D-15 | 2×2 工作台 MVP 用现有机器换皮，自定义设施后置 | 自定义设施需 AssetBundle/放置验证，风险高 | P2 再评估 |
| D-16 | 击杀奖励沿用原版公式，Mod 只追加降警觉 | 原版已有 100+(天数−引入日)、治安部 +8 | 避免重复奖励 |

## v0.3.1 — 调研后的技术事实修正

### 修正内容

| 项 | 原 v0.3 | 修正 |
|---|---|---|
| Mod 前置 | MelonLoader（Mono）+ Harmony | **不需要 MelonLoader**；游戏自带 `ModLoader` + `0Harmony 2.4.2` |
| 构建类型 | 假设 IL2CPP（v0.2） | **Mono**（Assembly-CSharp.dll + MonoBleedingEdge） |
| 改造体声望 | "第五派系" | **无 AddFaction 官方方法**；v0.3.1b 改为原版派系栏优先（Harmony/反射），ModData 回退 |
| 电量量纲 | 充能器 +6~10/晚 | 原版充能器 **+3/晚**；保留 100 kJ，主要靠电费/电池 |
| 夜间外出 | 不影响客人 | 闭店后不影响当日；原版**次日顾客 −1**、1 次/晚、三地点共用 |
| 科技树 | 自研 | 官方 `ModHelper.AddNetworkUpgrade` / `PerkDirectory.RegisterModUpgrade` |
| 特质互斥 | hook 特质选择 | 官方 `incompatiblePerks` |
| 存档 | 独立 JSON | 官方 `ModData` |
| 击杀奖励 | 按等级 60/150/400 | 沿用原版 `100+(天数−引入日)`，钳制 100–250；治安部 +8 |
| 2×2 工作台 | P0 | 高风险，MVP 用现有机器换皮；自定义设施后置 |

### 新增风险

- 原版改造体终局（引入 50 天存在度归 0 + 许可证 25 天）会"清除完毕"，ZERO 需接管/延缓。
- 展示柜是警报器：光学迷彩不能放展示柜。
- 误杀代价 250–750 犯罪值，豁免权无效。
- 版本口径冲突（build/1.0/0.46D/100-Rev1），manifest `GameVersions` 待用户确认。

### 仍需用户确认

1. 游戏实际版本号；2. 手术工具 200 cr 是否真实；3. 电费换算常量；4. 2×2 工作台是否值得做；5. 改造体声望 UI 形式；6. 100 kJ 是否保留。
