## 2. 电量 `power.json`

| key | 默认 | 说明 |
|---|---|---|
| `max` | 100 | 上限 kJ |
| `start` | 100 | 初始 |
| `dailyDrain` | 5 | 每日自然消耗 |
| `billRestore` | 5 | 付电费恢复 |
| `nightStayBonus` | 5 | 付电费且未外出的额外恢复 |
| `nightOutCost` | 5 | 夜间外出消耗 |
| `billPricePerKj` | 1.5 | 电费单价（信用点/kJ） |
| `batteryToKj` | 1.0 | 1 电池能量单位 → kJ |
| `chargerKjPerNight` | 3 | 充能器每夜给身体充能（原版基准 +3） |
| `dormantAlertPenalty` | 5 | 归零额外警觉 |
| `dormantDailyRecover` | 1 | 休眠期间每日自动恢复 |
| `dormantRescueDay` | 3 | 连续休眠第 3 天强制恢复 |
| `dormantRescueKj` | 10 | 强制恢复量 |
| `dormantUnlockOnRecover` | true | 恢复后当日解除封锁 |
| `lowPowerThreshold` | 20 | 低电量 UI 警示 |

**结算顺序（锁定）**：付电费 → 未外出奖励 → 自然消耗 → 夜间外出 → 充电 → 钳制 → 归零检查。

**净变化**：付+留 = **+5**；付+出 = **−5**；不付+留 = **−5**；不付+出 = **−10**。

### 2.1 原版电量对照与量纲校准（重要）

| 原版事实 | 数值 | 对 100 kJ 身体池的影响 |
|---|---|---|
| 机器单次耗电 | 2–24 kJ | 100 kJ 约等于 4–50 次机器运作 |
| 充能器 | +3 kJ/晚 | 从 0 充满需约 33 晚；仅作补充 |
| 能量阵列 | +2 kJ/晚（可叠加） | 补充更慢 |
| 自充电电池 | +4 kJ/晚 | 补充 |
| 电流转换器 | 价值 300；`ToCredits(energy, rate)` | 电费换算入口，rate 待实测 |
| 店铺电力服务费 | (天数÷10 + 5) × 难度倍率 | 可作为身体充电收费锚点 |

**结论**：100 kJ 身体池**可以保留**，但主要恢复应来自"付电费 + 留店"（+5/日）与电池/转换器，充能器只是补充；若实测觉得充能太慢，用科技树提升 `chargerKjPerNight` 或在难度预设里调整。若希望贴近原版量级，可改为 20–30 kJ 池或百分比条（见 `04` 风险项）。

### 4.3 检测公式

```
P_detect = baseDetect(tier)
         + alertness * 0.004
         + detectorRate(target) * 0.30
         - concealment(item) * 0.25
P_detect = clamp(P_detect, 0.02, 0.95)
```

- 检测成功 → **必报警【锁定】**。
- 容器遮蔽：净水药片 0.6 / 水质试纸 0.5 / 普通盒 0.3 / 无 0。

## 5. 感染 `infection.json`

```
P_infect = baseInfect(tier)
         * (1 - protection(target))
         * (1 - alertness * 0.004)
         * (1 + repBonus)
         - vaccinePenalty(target)
P_infect = clamp(P_infect, 0.02, 0.95)
```

| key | 默认 | 说明 |
|---|---|---|
| `relatedSpreadChance` | 0.20 | 关联 NPC 扩散概率 |
| `relatedSpreadCapPerNight` | 2 | 每夜扩散上限 |
| `repBonus60` | 0.10 | 声望 ≥60 |
| `repBonus80` | 0.15 | 声望 ≥80 |
| `vaccinePenalty` | 0.30 | 纳米疫苗惩罚（默认） |

**报到**：次日开店触发；接纳 → `HIDDEN` + 经费；拒绝 → `AUTONOMOUS`。

## 7. "人类"物品与手术 `human.json`

### 7.1 物品规格

| key | 默认 | 说明 |
|---|---|---|
| `itemId` | `aug.human` | 高级违禁品 |
| `grid` | 1×1【待定】 | 占格 |

| `searchRisk` | 高 | 被治安部搜查发现 → 没收 + 犯罪 |
| `sellable` | false | 不可正常出售 |

### 7.2 转化路径

| 路径 | 消耗 | 时间 | 成功率/进度 |
|---|---|---|---|
| 植入物过夜 | 1 个植入物 | 1 晚 | 100%（建议） |
| 手术改造 | 夜间外出机会 + 1 个医疗品 | 多晚累计 | 见公式 |
| 手术工具特例 | 夜间外出机会 + 手术工具（不消耗医疗品） | 1 晚 | 进度 +80 |

### 7.3 手术进度

```
progressPerNight = 20
                 + medValue * 0.5
                 + (hasSurgicalTool ? 80 : 0)
                 - protection(target) * 40
                 - vaccinePenalty(target) * 30
                 - alertness * 0.1
```

- 累计 ≥100 → 转化成功；
- 使用手术工具当晚 +80，通常 1–2 晚完成；
- 医疗品消耗：每次手术消耗 1 个；手术工具不消耗医疗品【待定：工具是否消耗】。

## 12. 不变量（实现必须保证）

1. 击杀改造体**不降低**改造体声望。
2. FRIEND 声望 `≤99`；只有 ZERO/CONVERTED 可达 100。
3. 检测到植入物 → **必报警**（除非难度项"首次预警"开启）。
4. ZERO 存档中不生成原版随机改造体。
5. 电量归零 → `DORMANT`，但不阻止开店（防死锁）。
6. `TASKED` 改造体不计入额外顾客，也不到店。
7. `AUTONOMOUS` 改造体不可被指派，但行动加警觉度。
8. "人类"物品不可正常出售；自主改造体不交付"人类"。
9. 科技树节点一旦解锁，另一轨不再扣费。
10. 改造经费只在"成功改造 + 玩家接纳"时发放。
