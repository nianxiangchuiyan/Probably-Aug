### 0.4 数值标注约定

- 已定数值直接写；未定数值写 **【待定：建议 X（区间 A~B）】**，并在附录 C 汇总。
- 配置键统一使用 `aug.<系统>.<项>`，例如 `aug.body.drainPerDay = 5`。
- 所有判定使用可复现随机（固定种子 + 判定点日志），便于 QA 回归。

### 0.5 全局判定优先级

1. **硬门槛**：玩家类型、电量、声望锁定、科技解锁、任务线门控 → 不满足直接拒绝并提示原因。
2. **互斥/容量**：特质互斥、改造槽、指令容量、每日次数上限。
3. **数值结算**：声望、电量、警觉度、信用点、物品。
4. **事件与报警**：暴露、检查、世界事件、顾客反应。
5. **持久化**：写存档、写日历、刷新 UI。

## 1. 开局与玩家初始化

### UC-01 开局特质"零号改造体"选择与"改造体危机"互斥

**涉及系统**：开局特质 / 原版事件池 / 玩家类型　　**适用玩家类型**：全部新开局

**前置条件**：
- 新游戏，已进入原版角色创建 / 特质选择界面；Mod 已完成特质注册。
- 原版"改造体危机"特质（或威胁事件）已在注册表中；若原版名称不同，互斥目标以配置 `aug.trait.rivalTraitId` 为准【待确认原版 ID】。

**触发条件**：玩家在特质列表点击"零号改造体"条目。

**主流程**：
1. 条目展示说明："初始改造体声望 +100 / 身体电量上限 100 kJ / 改造体科技树（科研免费、不可购买）/ 警觉度在逃逸进度满后激活 / 抑制原版改造体危机"；消耗特质点 **【待定：建议 2 点，与原版高级特质同档】**。
2. 系统读取互斥组 `augment_crisis`，检查已选特质：若含"改造体危机" → 拒绝选择，弹出互斥提示并高亮冲突项；若不含 → 置为可选中。
3. 玩家确认后写入：`playerType=Z`、`augReputation=100`、`bodyEnergy=bodyEnergyMax=100`、`escapeProgress=0`、`alertness=0（未激活）`、`traitFlags+="augment_zero"`。
4. 从本局原版威胁/事件池移除"改造体危机"及派生随机事件（`aug.crisis.suppress=true`），并把改造体生成来源标记为 Mod 控制（`aug.spawn.source=MOD_ONLY`）。
5. 进入第 1 天，加载店铺营业界面；电量条、改造体面板首次显示，未解锁项置灰。

**分支/异常**：
- **B1（不选零号）**：直接按原版开局 → `playerType=U`；无电量池、无科技树、声望 0；后续仅能通过 UC-02 的任务线门控转为 A 或 F。
- **B2（危机已发生）**：选零号前"改造体危机"已触发并生成改造体 → 提示"已生成的改造体不会被清除"；开局后这些改造体保留，按权威口径**全部视为已掌控**（Z 开局自带全部掌控），声望仍为 100，无额外接管消耗。
- **B3（特质点不足 / 被其他 Mod 占用）**：条目置灰并显示具体原因；不允许绕过确认流程。

**后置状态**：`playerType=Z`；`augReputation=100`；`bodyEnergy=100/100`；原版改造体危机已抑制；进入第 1 天。

**验收标准**：
- AC1：同时选择"零号改造体"与"改造体危机"时无法确认开局（确认按钮禁用或弹窗阻断），存档中不会同时存在两个特质标记。
- AC2：选择零号后，新存档满足 `playerType=="Z"`、`augReputation==100`、`bodyEnergy==100`。
- AC3：选零号后第 1~7 天内，原版"改造体危机"事件生成计数为 0（事件表/日志断言）。
- AC4：不选零号时 `playerType=="U"`，电量条与改造体科技树入口不可见。

**调参/配置点**：`aug.trait.pointCost=2`；`aug.trait.rivalTraitId`；`aug.crisis.suppress=true`；`aug.start.reputation=100`；`aug.start.bodyEnergy=100`。

**关联 UC**：UC-02、UC-07、UC-26、UC-30。

### UC-02 三类玩家初始化与"改造体之友"任务线门控

**涉及系统**：玩家类型初始化 / 任务线门控 / UI 可见性　　**适用玩家类型**：U、Z、A、F

**前置条件**：
- 新开局完成（U 或 Z），或已到达"改造体之友"任务线入口（`augReputation ≥ 30` 且玩家尚未选择过分支）。
- 原版任务线对话系统可用；Mod 只注册分支选项与状态迁移，不写剧情文本。

**触发条件**：开局确认；或任务线对话中选择"接受改造 / 作为朋友加入 / 拒绝"。

**主流程**：
1. 校验任务线门控：`augReputation ≥ 30` 时才显示"改造体之友"分支选项；<30 时入口锁定并提示"需改造体声望 ≥30"。
2. 玩家选择分支，系统写入类型与字段（对照表 0.1）：
   - **接受改造** → `playerType=A`；创建电量池 100/100；`alertnessActive=true`、`alertness=20`（权威口径）；声望沿用当前值；科技树为双轨（UC-25）；可上 100。
   - **作为朋友加入** → `playerType=F`；隐藏/移除电量相关 UI 与字段；声望沿用当前值并硬钳制 99；无改造体科技树；`alertnessActive=true`、`alertness=20`（权威口径）。
   - **拒绝/不参与** → 保持 `playerType=U`，改造体继续自主行动，原版击杀/放过流程不变。
3. 初始化公共状态：`augCount`（含 AUTONOMOUS）、`hiddenAugCount`、`controlledAugCount`。掌控规则（权威口径）：**Z 开局全部改造体视为已掌控**；**A 在声望 <100 时存在 AUTONOMOUS 改造体，达 100 全部收回**；**F 始终全部 AUTONOMOUS**。其余：`humanItemCount=0`、`nightOutUsed=false`、`assignments={}`、`techState`、`calendarEntries`。
4. 刷新 UI 可见性：电量条（Z/A）；改造体面板（全部类型）；科技树按钮（Z/A）；夜间指令入口（仅 Z/A 且 `augReputation==100`）；击杀改造体的原版入口（全部类型）。
5. 写存档 `saveVersion=1`（UC-30），记录分支选择，任务线入口不再重复出现。

**分支/异常**：
- **B1（A 迁移补齐）**：从 U 转入时补建电量池并激活警觉（20）；已存在的改造体为 AUTONOMOUS，声望 <100 时保持未被掌控、满 100 自动收回；`augReputation` 不变。
- **B2（F 迁移钳制）**：若迁移瞬间声望 ≥100（例如通过调试/其他 Mod），钳制到 99，并在声望面板显示"朋友上限"。
- **B3（重复触发）**：已选过分支后任务线入口不再出现（一次性），但 ≥30 的其他效果照常。
- **B4（朋友路线声望 99 后）**：任务线仍可触发但仅显示已选结果；不可转为 A（是否允许后悔转换【待定 Q3】）。

**后置状态**：类型与字段确定；UI 可见性确定；任务线入口关闭；公共状态已建立。

**验收标准**：
- AC1：三种类型初始化后，表 0.1 的每项字段/UI 可见性断言通过。
- AC2：声望 <30 时任务线分支选项不可见或置灰，且选择请求被系统拒绝。
- AC3：F 类型连续获得声望至 100 时，存储值始终保持 99，UI 显示 99/99。
- AC4：Z 在 `escapeProgress<100` 时 `alertnessActive=false`，警觉派生效果按 0 计算。
- AC5：A/F 初始化后 `alertnessActive=true` 且 `alertness==20`（权威口径）。

**调参/配置点**：`aug.alert.initialConverted=20`；`aug.alert.initialFriend=20`；`aug.rep.friendCap=99`；`aug.timeline.unlockRep=30`；`aug.start.controlledForZero=true`。

**关联 UC**：UC-01、UC-03、UC-09、UC-11、UC-20、UC-26、UC-30。

## 2. 身体电量

### UC-03 每日电量自然消耗与电费支付

**涉及系统**：身体电量 / 日结算 / 电费账单　　**适用玩家类型**：Z、A

**前置条件**：玩家为 Z/A；进入第 N 天；电力系统已加载，`bodyEnergy` 有值。

**触发条件**：每日开店结算（原版 NewDay 流程）；或玩家在电力面板点击"支付电费"。

**主流程**：
1. 日初自然消耗：`bodyEnergy = max(0, bodyEnergy − 5)`；电量条与日志更新（`aug.body.drainPerDay=5`）。
2. 电力面板显示本日电费明细：原版电网用量 + 改造体附加项（电流转换器取电、充能器耗电，见 UC-05）。
3. 玩家点击"支付电费"：扣除信用点 → `bodyEnergy = min(100, bodyEnergy + 5)`；账单状态置"已付"。
4. 闭店后记录夜间外出决策（UC-04，`nightOutUsed`）；外出与电费支付相互独立。
5. **日终判定**：若本日已付电费且当晚未外出 → 额外 `bodyEnergy += 5`（`aug.body.paidStayBonus=5`）；钳制 0~100；写入 `dailyEnergyDelta`。
6. 净变化（权威口径）：付+留 = +5；付+出 = −5；不付+留 = −5；不付+出 = −10。结算顺序固定在夜间指令之前（附录 B.4）。

**分支/异常**：
- **B1（不付电费）**：不恢复电量；沿用原版欠费/断电规则；当日只受自然消耗与夜间外出影响。
- **B2（电量不足以扣消耗）**：钳制为 0，置 `lowPower=true` 并红色警示；强制休眠在 UC-06 统一判定。
- **B3（信用点不足支付失败）**：原版电费接口拒绝，提示"信用点不足"，不恢复电量；可稍后再次尝试。
- **B4（重复支付）**：每个自然日只允许结算一次；重复点击提示"今日电费已结算"，不重复 +5。

**后置状态**：`bodyEnergy` 更新；账单已付/未付；`dailyEnergyDelta` 写入；`lowPower` 标志。

**验收标准**：
- AC1：不付电费且未外出：`bodyEnergy` 100→95（净 −5），不出现负值。
- AC2：付电费且未外出：`bodyEnergy` 100→100（−5+5+5，钳制上限；净 +5）。
- AC3：付电费且外出：100→95（净 −5）；未付且外出：100→90（净 −10）。
- AC4：一日内重复支付只恢复一次 5 kJ；电费明细可在电力面板展开。

**调参/配置点**：`aug.body.max=100`；`aug.body.drainPerDay=5`；`aug.body.billRestore=5`；`aug.body.paidStayBonus=5`；`aug.power.converterBillPerKJ`（见 UC-05）。

**关联 UC**：UC-04、UC-05、UC-06、UC-30。

### UC-04 夜间外出（闭店后行动）

**涉及系统**：夜间外出 / 电量 / 夜间行动互斥　　**适用玩家类型**：Z、A

**前置条件**：当日营业已结束、顾客已清场（闭店后）；电量 > 0；未处于强制休眠生效日。

**触发条件**：玩家在夜间结算面板点击"夜间外出"。

**主流程**：
1. 面板说明："外出发生在闭店后，**不影响今日营业、不会错过客人**；消耗 1 次夜间外出机会、身体电量 −5 kJ；当晚不能执行需要看店/在店的行动（手术改造等）。"
2. 玩家确认：`nightOutUsed=true`，`bodyEnergy=max(0, bodyEnergy−5)`；进入原版夜间场景（地图/区域）。
3. 外出只影响：电量变化；当晚可执行的其他夜间行动（手术改造消耗外出机会 → 与外出互斥；过夜转化是否阻断见 Q13）。夜间指令由改造体执行，不受玩家外出影响。
4. 返回或次日开始：写入日记录 `nightOutUsed`；当晚/次日被指派任务的改造体不进入店铺（与 UC-21 联动）。
5. 营业期顾客结果不受外出影响，不产生"错过客人"记录或惩罚。
6. **原版次日惩罚**：按原版夜间外出规则，次日普通顾客名额 **−1**（"短眠者"特性不计）；Mod 不额外加罚，只沿用。

**分支/异常**：
- **B1（电量不足 5 kJ）**：按钮禁用，提示"电量不足以支持夜间活动，请先充电或支付电费"（UC-05）。
- **B2（强制休眠生效日）**：夜间外出按钮不可用，提示当日无法进行改造体行动。
- **B3（外出遭遇改造体）**：声望 <0 或已背叛时，按原版袭击/战斗流程处理；带武器可反杀，反杀不降改造体声望（UC-08）。
- **B4（当晚已安排手术）**：手术已消耗外出机会 → 外出按钮置灰，需先取消手术（不消耗次数）。

**后置状态**：`nightOutUsed=true`；电量 −5（钳制 ≥0）；当晚行动窗口更新；与手术/转化互斥生效。

**验收标准**：
- AC1：夜间外出后 `bodyEnergy` 减少 5；不足 5 时钳制为 0，且不出现负值。
- AC2：同一天不能外出两次，第二次点击提示"今晚已外出"。
- AC3：夜间外出不影响当日营业结果（无顾客流失/错过客人惩罚）。
- AC4：外出当晚手术改造不可执行；电量 <5 kJ 或强制休眠生效日按钮禁用。
- AC5：次日普通顾客名额按原版规则 −1（"短眠者"特性不计）。

**调参/配置点**：`aug.body.nightOutCost=5`；`aug.nightOut.maxPerDay=1`；`aug.nightOut.blocksSurgery=true`；`aug.nightOut.blocksConversion=false`；`aug.nightOut.nextDayCustomerPenalty=1`（沿用原版）。

### UC-05 电池 / 充能器 / 电流转换器充电

**涉及系统**：电量 / 电池 / 充能器 / 电流转换器 / 电费　　**适用玩家类型**：Z、A

**前置条件**：背包或店内有电池（一次性/可充）或充能器；或已安装电流转换器；`bodyEnergy < 100`。

**触发条件**：玩家与设备交互：
- 电池物品菜单新增"直接为身体充电"；
- 充能器面板"身体充电"按钮；
- 电流转换器面板"接入电网取电"开关。

**主流程**：
1. 电池直充：读取电池可用能量，按转化率 `aug.body.batteryToKJ`（权威口径 =1.0，可配；暂定损耗 0）转为 kJ，`bodyEnergy=min(100, +转入量)`；一次性电池消耗销毁，可充电池扣能量/归零。
2. 充能器：设备需接电（电网或电池）；每夜按原版充能器基准 **+3 kJ/晚**（`aug.body.chargerKjPerNight=3`，科技树可提升）充入，充满为止；消耗的电池能量按原版记账，电网耗电进入电费。
3. 电流转换器：开启后从电网取电，给电池/充能器/身体供电；按原版 `CurrentConverterHelper.GetRate` / `ToCredits(energy, rate)` 计费，配置键 `aug.power.converterBillPerKJ=1.5`（**待实测**，以原版常量为准）；日结计入电费；取电期间身体充能按 kJ 折算。
4. 每次充能写日志（来源、数量、费用），供电费明细与 AC 校验。
5. 充能不消耗夜间外出机会；但受强制休眠生效日封锁限制（休眠日仍允许生命维持充电，见 UC-06）。

**分支/异常**：
- **B1（电池能量不足/类型不支持）**：提示可充入剩余量并部分充入；不支持类型置灰。
- **B2（充能器未通电）**：按钮禁用，提示"设备未接电"。
- **B3（转换器过载）**：电网负载超限 → 原版跳闸/断电，充电中断，已充入部分保留，已产生电费照计。
- **B4（F 玩家）**：所有充电入口隐藏（无电量池）。

**后置状态**：`bodyEnergy` 变化；电池/设备状态与消耗；电费账单增量；充能日志。

**验收标准**：
- AC1：电池直充后电量增加 = 电池消耗能量 × 转化率，且不超过 100。
- AC2：充能器单次/单夜充入量受速率上限，其耗电计入当日电费。
- AC3：转换器每取 1 kJ 产生配置对应电费，明细可查。
- AC4：F 玩家看不到任何充电入口。

**调参/配置点**：`aug.body.batteryToKJ=1.0`；`aug.body.chargerKjPerNight=3`（原版基准）；`aug.power.converterBillPerKJ=1.5`（待实测）；电池容量→kJ 映射表；`aug.body.allowChargeDuringHibernation=true`。

**关联 UC**：UC-03、UC-06、UC-10、UC-25。

### UC-06 电量归零：次日强制休眠

**涉及系统**：电量 / 日循环 / 警觉度　　**适用玩家类型**：Z、A

**前置条件**：玩家为 Z/A；当日闭店结算时 `bodyEnergy == 0`。

**触发条件**：日终结算（DAY_END）检测到 `bodyEnergy == 0`。

**主流程**：
1. 日终触发：置 `pendingHibernation=true`，提示"电量耗尽，明日将强制休眠"；`alertness += 5`（若 Z 未激活则记录待激活增量）。
2. 日终自动恢复：`bodyEnergy = max(bodyEnergy, 1)`（每日自动恢复 1 kJ，次日至少 1 kJ）；若连续 `hibernationDays≥3`（连续 3 天触发休眠、无法维持）→ 强制恢复 10 kJ 并重置计数（防死锁）；F 永不进入。
3. **次日生效**：`DAY_START` 时 `forcedHibernation=true`，封锁改造体行动（夜间指令、夜间外出、制造/销售植入物、转化/手术）；原版当铺营业照常，不产生软锁。
4. 休眠日允许"生命维持"：充电（UC-05）或支付电费；若电量恢复到 >0，默认当日解除封锁（`aug.body.hibernationUnlockOnRecover=true`），解封后可行动。
5. 日历记录休眠日；连续休眠计数 `hibernationDays` 用于第 2 步的强制恢复。

**分支/异常**：
- **B1（休眠日付电费/充电恢复）**：默认当日解除封锁（可配），已增加的警觉度不返还。
- **B2（连续 3 天 0 kJ）**：强制恢复 10 kJ 并解除休眠，不再追加额外警觉（防死锁）。
- **B3（F 玩家）**：无电量池，永不进入该状态。
- **B4（休眠生效日已分配夜间指令）**：当日指令作废，改造体回 HIDDEN；不产生收益、不扣额外警觉（附录 C-Q8）。

**后置状态**：`pendingHibernation`/`forcedHibernation` 记录；次日改造体行动封锁；`alertness +5`（触发日）；电量自动恢复；日历条目。

**验收标准**：
- AC1：电量归零当日**不立即封锁**；次日 `DAY_START` 起改造体行动被封锁（时序断言）。
- AC2：次日原版当铺营业仍可进行，不出现无法继续游戏的软锁。
- AC3：每日自动恢复 1 kJ；连续 3 天触发休眠时强制恢复 10 kJ 并重置计数。
- AC4：休眠日充电/付电费后按配置解除封锁（默认解除）。
- AC5：触发当日 `alertness` 增加 5。

**调参/配置点**：`aug.body.hibernationAlert=5`；`aug.body.hibernationRecoverDaily=1`；`aug.body.hibernationForcedRecover=10`；`aug.body.hibernationForcedDays=3`；`aug.body.hibernationUnlockOnRecover=true`。

**关联 UC**：UC-03、UC-04、UC-05、UC-20、UC-26。

### UC-08 声望流失、背叛锁定与击杀规则

**涉及系统**：改造体声望 / 任务线分支 / 战斗与击杀　　**适用玩家类型**：Z、A、F、U

**前置条件**：`augReputation` 可变；玩家可接触改造体（店内/外出）或已满足任务线分支条件。

**触发条件**：击杀改造体；任务线选择"背叛改造体"；对改造体敌对行为（举报、打砸、出售给治安部）。

**主流程**：
1. **击杀**：走原版击杀奖励管线（信用点、治安部声望），追加：**改造体声望锁定、不变化**（`augReputation += 0`）；`alertness -= 3`（每日前 3 次全额、之后 −1，UC-28）；记录击杀计数。
2. **敌对行为（非击杀）**：按行为表扣声望（如拒绝请求 -1、向治安部举报 -10、出售其位置 -20）【待定】。
3. **背叛**：任务线选择"背叛" → 二次确认（不可撤销）→ `augReputation=-100`、`repLocked=true`；`augCount` 大幅减少（建议保留 20%【待定】）；店铺进入"被打砸"事件池；玩家外出遭遇袭击概率提升。
4. 锁定后：所有声望获取失败；改造体顾客生成率降为 0（普通顾客照常）；若 `augCount` 归零 → 触发"改造体灭绝"结果：治安部表彰 + 1500 信用点（仅一次）。
5. 击杀与背叛判定完全独立：击杀永远不触发 -100 锁定。

**分支/异常**：
- **B1（击杀最后一名改造体）**：击杀本身不降声望；若此前已背叛且数量归零 → 触发灭绝奖励。
- **B2（背叛后悔）**：无恢复途径，仅提示读档；不提供"洗白"任务。
- **B3（声望 100 时背叛）**：先扣到 -100，立即清除全局掌控，夜间指令入口消失。
- **B4（击杀普通 NPC）**：只走原版犯罪/治安处理，不影响改造体声望。

**后置状态**：声望与锁定状态；改造体数量；店铺/外出风险状态；灭绝奖励可能触发；日志与日历。

**验收标准**：
- AC1：击杀改造体后 `augReputation` 不变，且获得原版信用点、治安部声望、警觉度降低。
- AC2：背叛后声望恒为 -100，后续 `AddAugReputation` 全部无效。
- AC3：背叛后改造体顾客生成率为 0。
- AC4：仅击杀（未背叛）不会使声望锁定或变成 -100。

**调参/配置点**：`aug.rep.killPenalty=0`；`aug.rep.betrayValue=-100`；`aug.rep.betraySurvivorRate=0.2`；敌对行为扣分表；`aug.extinction.reward=1500`。

**关联 UC**：UC-07、UC-09、UC-27、UC-28、UC-29。

### UC-09 声望阈值引擎（20/30/40/60/80/100 与朋友 99 上限）

**涉及系统**：改造体声望 / 阈值效果 / UI / 日历　　**适用玩家类型**：Z、A、F、U

**前置条件**：`augReputation` 已变化或每日开店。

**验收标准**：
- AC1：声望 19→20 且存在 1 名无任务 HIDDEN 改造体 → 次日出现 1 名额外改造体顾客；若所有 HIDDEN 改造体均有任务 → 不出现。

- AC3：声望 <40 时日历不显示未掌控改造体行动；≥40 显示且只读。
- AC4：声望跌破阈值后对应效果关闭，且日志记录阈值变化。

**调参/配置点**：阈值数组；`aug.rep.extraCustomerCount=1`；`aug.rep.qualityMult=1.25`；`aug.rep.giftChance=0.25`；`aug.rep.giftValueTier`。

**关联 UC**：UC-02、UC-07、UC-08、UC-19、UC-20、UC-30。

### UC-11 基础 / 可食用 / 水溶性植入物制造

**涉及系统**：制造 / 植入物层级 / 科技树　　**适用玩家类型**：Z、A

2. 可食用 / 水溶性：需科技节点；产物 `layer=ingestible|waterSoluble`、`contrabandLevel=critical`；可放入食物 / 水容器销售；感染成功率加成。
3. 品质判定：`quality = base + 科技加成 + 材料品质修正 + RNG`；品质影响售价、感染率、被发现概率。
4. 制造成功：产物入背包，写入层级/品质/违禁等级/可遮掩标记。
5. 制造失败（建议 10%，材料 50% 返还【待定】）：产出废品或空，记录日志。

**分支/异常**：
- **B1（未解锁可食用/水溶）**：配方灰显并提示所需节点（技术树 UC-25）。
- **B2（材料品质低）**：产物品质降低，感染率与售价按品质修正。
- **B3（背包满）**：产物掉落到工作台输出格，需手动取走；次日未取走按原版掉落规则处理。
- **B4（制造期间被检查）**：工作台按"高级违禁品制造设备"判定风险，复用原版违禁品检查流程【待定：是否需要额外犯罪标记】。

**后置状态**：植入物物品（层级/品质/违禁等级）；材料与电力消耗；失败记录。

**验收标准**：
- AC1：基础/可食用/水溶性产物带正确 `layer` 与 `contrabandLevel` 标签。
- AC2：水溶性植入物可被放入食物/水容器物品（与 UC-13 联动）。
- AC3：品质计算可复现（固定种子下结果一致，日志含各项修正）。
- AC4：未解锁层级时无法制造。

**调参/配置点**：三层配方与材料；`aug.craft.failChance=0.1`；品质权重表；违禁等级映射。

**关联 UC**：UC-10、UC-12、UC-13、UC-16、UC-25。

### UC-12 伪装型 / 光学迷彩 / 剧情特制植入物制造

**涉及系统**：制造 / 植入物层级 / 科技树 / 事件门控　　**适用玩家类型**：Z、A（剧情特制按 storyFlag 门控）

**前置条件**：已解锁"伪装型""光学迷彩"节点；剧情特制需任务线/事件标志（仅状态门控，不含剧情文本）。

**触发条件**：玩家在工作台选择对应配方并制造。

**主流程**：
1. 伪装型：配方（建议：电子零件 2 + 伪装外壳 1 + 生物材料 1【待定】）；产物带 `disguiseTag=<合法物品模板>`；检查/顾客视角按伪装物判定（UC-14）。
2. 光学迷彩：需高科技材料（建议：电子零件 3 + 光学纤维 2【待定】）；产物 `invisibleToCustomer=true`、`price=0`；顾客不可见但会顺手拿走（UC-14）。
3. 剧情特制：仅当 `storyFlag` 满足时解锁配方；产物 `plotItem=true`，不可交易、不可复制；本用例只验证配方门控与物品属性，不验证剧情演出。
4. 制造后写入层级/特殊属性；科技树面板同步显示解锁状态。
5. 同类配方共享品质/失败规则（UC-11）。

**分支/异常**：
- **B1（迷彩被治安部检查）**：检查仍按鉴别率发现（"不可见"仅对顾客生效）；被发现的报警流程见 UC-15。
- **B2（storyFlag 缺失）**：剧情特制配方不可见；读档后若标志恢复则自动出现，不报错。
- **B3（伪装目标被原版移除/改名）**：回退到"通用合法物品"外观，提示玩家。
- **B4（材料不足）**：同 UC-10-B3。

**后置状态**：高级植入物（含特殊属性）；科技解锁状态；日志记录。

**验收标准**：
- AC1：光学迷彩物品 `price=0` 且不出现在顾客购买目标列表。
- AC2：伪装型植入物被检查时使用伪装物判定而非植入物判定（检查结果可观测）。
- AC3：未满足 `storyFlag` 时剧情特制配方不可见；满足后可制造且 `plotItem=true`。
- AC4：三类产物 tooltip 显示层级、品质、特殊属性。

**调参/配置点**：各层配方/材料；`aug.disguise.quality`；迷彩检查可见性开关 `aug.camo.hiddenFromInspection=false`；剧情配方 flag 名。

**关联 UC**：UC-11、UC-14、UC-15、UC-25。

## 5. 植入物销售

### UC-13 容器遮掩销售（把植入物混入包装物品）

**涉及系统**：销售 / 容器 / 检查 / 感染队列　　**适用玩家类型**：Z、A、F（F 可转卖但不制造）

**前置条件**：背包有基础植入物；有带"容器/包装"标签的原版物品（药盒、食品盒、工具箱等）；柜台/货架有空位。

**触发条件**：玩家把植入物拖入容器物品，或对容器选择"装填"。

**主流程**：
1. 装填校验：容器剩余格数 ≥ 植入物占格，且容器未被标记为"透明/不可遮掩"；通过后植入物 `concealedIn=<containerId>`。
2. 容器 tooltip 只显示容器本身信息，不显示内部植入物名称/层级；容器获得 `containsContraband=true`。
3. 上架：顾客看到的是容器物品，价格 = 容器价格 + 植入物加价（由玩家定价）；交易成功 → 植入物随容器售出。
4. 暴露判定：顾客检查/购买时按 UC-15 计算；容器遮掩率 `aug.sale.containerConceal`（建议 70%）降低发现概率但不为 0。
5. 售出后写 `soldImplantQueue`（购买者、层级、品质、日期），进入次日夜间感染判定（UC-16）。

**分支/异常**：
- **B1（容器本身是违禁品/被盗物）**：违禁等级取高者；检查/报警风险叠加。
- **B2（顾客嫌贵/议价）**：正常议价；可降价，低于成本只影响经济不影响系统状态。
- **B3（顾客当场拆开容器）**：检查成功 → 进入 UC-15 报警流程，植入物被查获/顾客离开。
- **B4（容器尺寸不足）**：提示"尺寸不符"，装填失败。

**后置状态**：植入物售出或未售；容器状态；感染队列条目；犯罪风险。

**验收标准**：
- AC1：装填后容器 tooltip/顾客视角不显示植入物信息（信息隐藏生效）。
- AC2：发现概率按容器遮掩率计算，可复现（固定种子）。
- AC3：售出后次日该顾客进入感染判定队列（UC-16）。
- AC4：容器尺寸不足时无法装填。

**调参/配置点**：`aug.sale.containerConceal=0.7`；容器容量映射；植入物定价系数；可遮掩容器标签白名单。

**关联 UC**：UC-11、UC-14、UC-15、UC-16。

### UC-14 伪装成合法物品与光学迷彩 0 信用点摆放

**涉及系统**：销售 / 伪装 / 光学迷彩 / 顾客鉴别　　**适用玩家类型**：Z、A、F

**前置条件**：持有伪装型或光学迷彩植入物；货架/展示柜有空位。

**触发条件**：玩家在销售界面选择"伪装成合法物品"，或对光学迷彩选择"摆放（0 信用点）"。

**主流程**：
1. 伪装上架：选择合法物品模板（如药品、工具、饰品）→ 生成伪装品，显示名/图标/分类沿用模板，`disguise=true`；玩家可定价（0~原价）。
2. 顾客浏览/交易时按鉴别率（UC-27）与顾客"暴露能力"判定识破；识破 → UC-15 报警流程。
3. 光学迷彩摆放：物品以 0 信用点放入货架，顾客不可见、不进入购买意向；每个顾客离店时按 `aug.sale.camouflageTakeChance`（建议 15%/客/件）判定"顺手拿走"。
4. 被拿走视为售出（收入 0），进入感染判定队列；未被拿走则继续留在货架。
5. 玩家可随时下架/收回迷彩物品；收敛后不消耗。

**分支/异常**：
- **B1（伪装模板本身是违禁品/赃物）**：叠加原版原罪，报警风险提高。
- **B2（顾客识破但选择不报警）**：仅流失顾客；是否报警由 UC-15 配置决定（默认发现必报警）。
- **B3（迷彩物品被清洁工/普通顾客误清理）**：小概率丢失（建议 5%/夜【待定】），不产生感染。
- **B4（断货）**：被拿走后需重新摆放新物品。

**后置状态**：伪装/迷彩物品售出或留在货架；感染队列；识破/报警记录；0 收入记录。

**验收标准**：
- AC1：伪装品在顾客视角显示为模板合法物品（tooltip/名称断言）。
- AC2：光学迷彩标价 0，不出现在顾客购买意向，但离店有配置概率被拿走。
- AC3：识破后按配置进入报警判定（默认 100%）。
- AC4：迷彩被拿走不产生任何销售收入。

**调参/配置点**：`aug.sale.disguiseQuality`；`aug.sale.camouflageTakeChance=0.15`；`aug.sale.camoCleanLoss=0.05`；伪装模板白名单。

**关联 UC**：UC-12、UC-13、UC-15、UC-16、UC-27。

### UC-15 暴露判定与"被发现必报警"

**涉及系统**：检查 / 犯罪 / 治安部 / 顾客　　**适用玩家类型**：Z、A、F

**前置条件**：顾客/检查官正在交易或检查；物品可能暴露（伪装/容器/迷彩被发现）。

**触发条件**：鉴别判定成功；或顾客主动拆开容器；或治安部检查命中违禁品。

**主流程**：
1. 计算发现概率：`P = 层级基础发现率 × 顾客鉴别系数 × (1 − 遮掩率或伪装质量) × 警觉度系数`（系数见 UC-27）；写入 `exposed=true`。
2. 基线硬规则：**被发现必定报警**。立即调用原版犯罪/报警接口（`CommitCrime("contraband_sale")`），治安部声望下降，`alertness += 5`。
3. 走原版检查/罚款/逮捕流程（如有检查官在场）；普通顾客则触发"顾客报警"对话与离店等待治安。
4. 该顾客标记 `reported=true`，移出感染判定队列（不再被改造）。
5. 记录日历事件与日志（物品、顾客、发现方式）；玩家可阅读检查单。

**分支/异常**：
- **B1（贿赂成功）**：调用原版检查贿赂接口，罚款取消或减半，信用点扣除，警觉度增加减半【待定】。
- **B2（玩家击杀报警顾客）**：走原版犯罪流程，改造体声望不变（普通顾客），警觉度上升。
- **B3（检查官 vs 普通顾客）**：分别走原版检查 UI 与顾客报警流程，不混用。
- **B4（证据不足：物品已售出/已销毁）**：按原版"证据不足"处理，警觉度增加减半【待定】。

**后置状态**：犯罪记录；`alertness` 增加；顾客状态；检查单/罚金；日历事件。

**验收标准**：
- AC1：鉴别成功时 100% 触发报警，无静默忽略路径。
- AC2：报警后警觉度按配置增加，且该顾客不进入感染队列。
- AC3：贿赂/击杀可改变处理结果，但默认路径为报警。
- AC4：暴露事件写入日历与日志，读档后可复现。

**调参/配置点**：`aug.alert.reportGain=5`；各层级基础发现率；贿赂费用与警觉减半系数；证据不足系数。

**关联 UC**：UC-13、UC-14、UC-16、UC-27。

## 6. 感染判定与改造体顾客

### UC-16 夜间感染判定与次日"报到"

**涉及系统**：感染 / 日结算 / NPC 状态 / 日历　　**适用玩家类型**：Z、A、F（任何做出售者）

**前置条件**：前一日/当夜存在售出植入物记录（`soldImplantQueue`）或光学迷彩被拿走的顾客；顾客已离店。

**触发条件**：夜间结算（正在原版日终界面确认前）。

**主流程**：
1. 遍历售出队列，对每个购买者/拿走者判定：
   `感染率 = 层级基础率 + 品质修正 + 可食用/水溶加成 − 警觉度惩罚 − 顾客防护修正`（见 UC-27），基础建议 30%（20%~40%）。
2. 成功 → 顾客 `infected=true`、`hidden=true`，加入改造体名册，`hiddenAugCount+1`；生成次日"报到"事件（写入日历/顾客队列）。
3. 关联 NPC：若该顾客到店时带有同伴/随从（原版顾客组），按建议 50% 概率一并感染为HIDDEN 改造体；同样隐藏。
4. 失败 → 顾客保持普通；按基线"销售后每晚判定"仅判定一次（销售次夜），失败即结束【待定 Q4】。
5. 次日报到：开店时该顾客（及关联 NPC）以普通顾客身份进店，触发"报到"交互（占位文本）；玩家确认/接待后其正式成为HIDDEN 改造体顾客，可参与 ≥20 计数（UC-19）与 UC-17 行为；玩家未营业则顺延，最多保留 `aug.infect.reportKeepDays`（建议 3 天）。

**分支/异常**：
- **B1（报到前顾客死亡/离开）**：移除条目，若已计入 `hiddenAugCount` 则扣回。
- **B2（被感染者是治安部/上层身份）**：感染率 ×0.6，报到时可能携带检查事件【待定】。
- **B3（玩家当日未营业/强制休眠）**：报到顺延不丢失，超过保留期离开并记录。
- **B4（关联 NPC）**：若同时感染，两者都计入HIDDEN 改造体；额外顾客名额（UC-19）只消耗 1 个。

**后置状态**：HIDDEN 改造体 +1~2；次日报到事件；日历/名册更新；`augCount`/`hiddenAugCount` 更新。

**验收标准**：
- AC1：售出植入物后仅当夜判定一次，成功者次日必定出现报到事件。
- AC2：报到后该 NPC `hidden==true` 并计入 `hiddenAugCount`。
- AC3：关联 NPC 按配置概率同步感染，且不重复计数。
- AC4：未营业日报到顺延，超过保留天数条目移除且不崩溃。

**调参/配置点**：`aug.infect.baseChance=0.3`；层级/品质加成表；`aug.infect.relatedNpcChance=0.5`；`aug.infect.reportKeepDays=3`；高身份修正 0.6。

**关联 UC**：UC-13、UC-14、UC-17、UC-19、UC-29、UC-30。

### UC-17 改造体顾客行为（购买 / 捐赠 / 请求物品）

**涉及系统**：顾客行为 / 声望 / 请求系统　　**适用玩家类型**：Z、A、F

**前置条件**：存在HIDDEN 改造体（`hiddenAugCount≥1`）；营业中；当日顾客队列生成。

**触发条件**：HIDDEN 改造体作为顾客进入店铺。

**主流程**：
1. 生成：`isAugment=true`、`hidden=true`；外观沿用普通顾客；预算/物品质量按声望阈值修正（≥60 生效，UC-09）。
2. 购买：正常交易；额外提供"友好价"（降价 10% 换声望 +1，每顾客每日 1 次【待定】）；成交走 UC-07。
3. 捐赠：建议 10%/顾客概率进入捐赠行为，随机赠送信用点（50~200）或物品（医疗品/材料）；不占交易次数，声望 +1（每日上限）。
4. 请求物品：以原版请求/订单形式提出需求（医疗品、材料、日用品）；玩家在请求面板交付 → 声望 + 信用点 + 好感；不交付则 3 天后过期。
5. 所有行为写入改造体面板"关系"页（隐藏/TASKED/已掌控/冷却）。

**分支/异常**：
- **B1（声望 <0 / 已背叛）**：不再生成改造体顾客；HIDDEN 改造体转为敌对（打砸/袭击，见 UC-08）。
- **B2（请求物品是违禁品/"人类"物品）**：交付照常触发犯罪/暴露判定。
- **B3（玩家击杀该顾客）**：不降声望（UC-08），但失去该改造体，`hiddenAugCount−1`。
- **B4（请求过期与补货同日）**：日初先检查过期，再进入营业，避免"当天补货仍过期"的边界。

**后置状态**：声望/信用点/物品变化；顾客状态；请求状态；关系记录。

**验收标准**：
- AC1：HIDDEN 改造体顾客至少可触发购买、捐赠、请求三类行为各一次。
- AC2：捐赠/友好价的每日上限生效，无法无限刷声望。
- AC3：请求交付/失败/过期状态正确，且日历提示过期日。
- AC4：背叛锁定后不再生成改造体顾客。

**调参/配置点**：`aug.client.donateChance=0.1`；捐赠价值区间；`aug.client.requestExpireDays=3`；友好价折扣与每日上限。

**关联 UC**：UC-07、UC-16、UC-18、UC-19、UC-21、UC-30。

### UC-18 "指出伪装破绽"奖励互动

**涉及系统**：顾客互动 / 声望 / 信用点 / 物品奖励　　**适用玩家类型**：Z、A、F

**前置条件**：HIDDEN 改造体顾客到店；玩家与其对话/交互；该顾客不在冷却中。

**触发条件**：玩家在顾客交互菜单选择"你伪装得不像人类"（新增选项）。

**主流程**：
1. 可见性：仅 `isAugment==true && hidden==true` 且冷却期满（建议 7 天）的顾客显示该选项。
2. 选择后播放占位反应文本（紧张/承认/恼怒按属性），随后结算：声望 +3（建议 2~5）、信用点 +50~150（按身份 tier）、20% 概率物品奖励【待定】。
3. 伪装质量修正：高伪装/高品质顾客可能"否认成功"，奖励减半或无奖励，但冷却照常生效【待定】。
4. 结算后写 `lastPointOutDay[augId]=day`；顾客当次访问标记"已被指出"，可继续交易，不强制离店。
5. 记录日志与关系页；隐藏状态不解除，也不触发报警（除非 B3）。

**分支/异常**：
- **B1（冷却内重复指出）**：选项隐藏/置灰，显示"已指出过（剩余 N 天）"。
- **B2（顾客恼怒离店）**：取消购买但默认不报警；损失交易机会。
- **B3（治安部在场时指出）**：可能暴露该改造体，触发检查事件【待定：建议 30% 概率】。
- **B4（误指普通顾客）**：选项对非改造体不可见；调试强制触发时无奖励、无冷却。

**后置状态**：声望/信用点/物品奖励；冷却记录；顾客状态；日志。

**验收标准**：
- AC1：该选项仅对HIDDEN 改造体顾客显示，普通顾客不显示。
- AC2：单次奖励符合配置区间，同一顾客 7 天内不可重复领取。
- AC3：指出不解除隐藏状态，默认不触发报警。
- AC4：奖励写入日志，读档后冷却与奖励记录一致。

**调参/配置点**：`aug.point.repGain=3`；`aug.point.creditBase=100`；`aug.point.itemChance=0.2`；`aug.point.cooldownDays=7`；`aug.point.inspectionRisk`。

**关联 UC**：UC-17、UC-19、UC-30。

### UC-19 声望 ≥20：每天额外一名 HIDDEN 改造体顾客

**涉及系统**：声望阈值 / 顾客调度 / 日结算　　**适用玩家类型**：Z、A、F

**前置条件**：`augReputation ≥20`；存在至少 1 名HIDDEN 改造体；未处于背叛锁定。

**触发条件**：每日开店顾客生成阶段。

**主流程**：
1. 日初统计：`eligible = hiddenAugCount − 有夜间任务的 HIDDEN 改造体数`（任务判定见 UC-20/21）。
2. 若 `eligible ≥1` 且声望 ≥20 → 当日顾客队列额外插入 1 名改造体顾客，不替换原版顾客，仅追加；标记 `extraAugmentSlotUsed=true`。
3. 抽取对象：从HIDDEN 改造体名册中排除"TASKED/当日已到访（如启用）/死亡/冷却"；若名册为空但计数异常 >0 → 不生成并打错误日志。
4. 每日最多 1 次；生成后当日不再重试；玩家接待结果不影响是否生成。
5. 与声望 <20、锁定 -100、F/A 的类型无关（F 同样享受 ≥20 效果）。

**分支/异常**：
- **B1（所有 HIDDEN 改造体均有任务）**：`eligible=0` → 当日不生成额外顾客（基线明确）。
- **B2（HIDDEN 改造体当日已到访过）**：按配置允许/拒绝重复到访（建议允许，改造体可每天来；开启时需排除冷却）【待定】。
- **B3（声望当天跨过 20）**：当日日初已结算 → 次日生效（建议，避免中途插入顾客队列）。
- **B4（声望锁定 -100）**：不生成。

**后置状态**：顾客队列 +1；`extraAugmentSlotUsed`；日历/日志记录"额外改造体顾客"。

**验收标准**：
- AC1：声望 20、HIDDEN 改造体 2 名且均无任务 → 当日改造体顾客计数 ≥1（额外名额生效）。
- AC2：所有 HIDDEN 改造体被指派任务 → 当日不生成额外顾客。
- AC3：声望 19 或 -100 → 不生成额外顾客。
- AC4：每日最多 1 名额外改造体顾客，不因多次营业/读档重复生成。

**调参/配置点**：`aug.rep.extraThreshold=20`；`aug.rep.extraCustomerCount=1`；`aug.rep.allowRepeatVisit=false`。

**关联 UC**：UC-09、UC-16、UC-17、UC-20、UC-21、UC-30。

## 7. 夜间指令

### UC-20 夜间指令分配（七类指令）

**涉及系统**：夜间指令 / 声望 100 掌控 / 调度容量　　**适用玩家类型**：Z、A

**前置条件**：`augReputation==100` 且玩家已掌控全部改造体；闭店进入夜间结算；存在空闲改造体。

**触发条件**：玩家在夜间结算面板点击"分配夜间指令"。

**主流程**：
1. 面板列出已掌控改造体及状态：空闲 / TASKED / 受伤 / 冷却；每名每晚最多分配 1 条指令。
2. 七类指令：拾荒、赚取信用点、联络人脉、进行研究、抓捕人类进行改造、提供货物、制造世界事件；每条显示预估收益、警觉度增量、成功概率、风险提示。
3. 玩家选择 → 写 `assignment[augId]=type`，状态置 `TASKED`；支持"重复上一晚"批量分配。
4. 调度容量校验：可分配数量 ≤ `aug.dispatch.capacity`（默认 3，科技树可升至 4/5【待定】）；超出时提示扩容节点。
5. 确认后进入夜间结算（UC-21）；未分配的改造体保持 IDLE。

**分支/异常**：
- **B1（声望 <100 或 F）**：入口不可见/置灰，提示"需声望 100 并掌控全部改造体"。
- **B2（受伤/被扣押）**：该改造体不可分配，显示原因与恢复天数。
- **B3（全部有任务）**：提示"暂无空闲改造体"；可撤回未执行的指令（撤回不消耗夜晚）。
- **B4（强制休眠）**：夜间指令面板不可打开；已分配指令按 UC-06-B4 处理（取消/保留按配置）。

**后置状态**：`assignments` 写入；改造体状态；容量占用；UI 汇总。

**验收标准**：
- AC1：仅 Z/A 且声望 100 时出现夜间指令入口。
- AC2：每名改造体每晚最多 1 条指令，分配数不超过调度容量。
- AC3：面板列出全部 7 类指令，数值提示与结算结果一致。
- AC4：撤回后改造体回 IDLE，当晚不结算该指令。

**调参/配置点**：`aug.dispatch.capacity=3`；七类指令收益/成功率/警觉增量表；受伤恢复天数。

**关联 UC**：UC-09、UC-19、UC-21、UC-25、UC-26。

### UC-21 夜间指令结算：警觉度增量、世界事件与"有任务不来店"

**涉及系统**：夜间指令 / 警觉度 / 世界事件 / 顾客队列　　**适用玩家类型**：Z、A

**前置条件**：夜间结算开始；`assignments` 非空；玩家已确认。

**触发条件**：日终结算（原版日终界面确认后、次日开店前）。

**主流程**：
1. 按固定顺序逐条结算（建议：研究 → 拾荒 → 赚取信用点 → 提供货物 → 联络人脉 → 抓捕人类 → 制造世界事件），每条判定：
   - 拾荒：按成功率获得材料/电子零件/旧零件。
   - 赚取信用点：收益 = 基础 × 身份系数 × (1 − 警觉系数)。
   - 联络人脉：产出情报/请求/新顾客线索，降低后续指令难度【待定】。
   - 进行研究：产出研究点，推进科技树（UC-25）。
   - 抓捕人类：成功生成"人类"物品（UC-22）；失败增加暴露风险。
   - 提供货物：把物资放入店铺仓库/完成顾客请求/按指令出售。
   - 制造世界事件：见步骤 3。
2. 每条指令按表增加警觉度（建议）：拾荒 +1、赚信用点 +1、联络人脉 +1、研究 +1、抓捕 +3、提供货物 +1、世界事件 +5；警觉度钳制 0~100。
3. 世界事件：抽事件表（供电事故、治安突查、物资短缺等），持续 1~3 天；可选择"强力压制"短期压低警觉度 −10，冷却 7 天，冷却结束后反弹 +8 且期间犯罪发现率 +20%【待定】；写入世界状态与日历。
4. 任务结果：成功/失败/受伤（受伤概率 = f(指令风险, 警觉度)）；TASKED 改造体次日转 IDLE 或 受伤 1~3 天。
5. "有任务不来店"：顾客生成时排除 `assignment≠NONE` 的改造体；任务失败/受伤者同样不来店（当晚与次日顾客队列均排除）。
6. 汇总面板显示当晚收益/损失/警觉变化；玩家确认后进入次日。

**分支/异常**：
- **B1（抓捕失败被目击）**：`alertness += 额外 3~5`，次日可能触发治安部检查事件。
- **B2（世界事件强力压制）**：按步骤 3 的冷却/反弹/副作用执行，期间日历显示"压制中"。
- **B3（指令前置失效，如无人类可抓）**：改造体回 IDLE，不产生收益；是否计警觉按配置（建议仍 +1）【待定】。
- **B4（改造体死亡/被捕）**：从名册移除，TASKED断；声望不变；调度容量释放。

**后置状态**：资源/研究点/物品/人类物品；`alertness`；改造体状态；世界事件；次日顾客排除生效；日历条目。

**验收标准**：
- AC1：每条指令按配置表结算警觉度增量，结算面板显示逐条明细。
- AC2：被指派任务的改造体不出现在当晚/次日店铺顾客队列。
- AC3：世界事件在日历可见，持续时间/冷却/反弹数值按配置可复现。
- AC4：研究指令产出的研究点正确进入科技树进度。

**调参/配置点**：七类指令收益/成功率表；警觉增量表；受伤概率；世界事件表/冷却/反弹；`aug.dispatch.excludeTaskedFromShop=true`。

**关联 UC**：UC-19、UC-20、UC-22、UC-25、UC-26、UC-30。

## 8. "人类"违禁品与手术改造

### UC-22 "人类"违禁品获取与保存风险

**涉及系统**：高级违禁品 / 抓捕指令 / 检查 / 改造流程　　**适用玩家类型**：Z、A（F 可通过交易获得但不可转化，建议）

**前置条件**：玩家指派抓捕人类成功（UC-21）；或改造体自主抓捕（不交付）。

**触发条件**：夜间结算中"抓捕人类"指令成功；或自主改造体行动结算。

**主流程**：
1. 玩家指派成功 → 生成高级违禁品"人类"物品，进入玩家背包/指定容器；`humanItemCount+1`。
2. 物品属性：违禁等级 Critical；占格 2x2【待定：建议 1x2 便于运输】；不可叠加；`plotItem=false`。
3. 保存风险：店内每过一夜按 `aug.human.decayRisk`（建议 5%/夜）判定；柜台/展示柜风险更高（建议 10%，仓库 3%）；触发 → 治安部检查或物品损坏。
4. 被检查发现：按原版违禁品流程罚金/没收/逮捕；`alertness += 10`；物品销毁。
5. 自主执行差异：非玩家指派的抓捕成功 → **不生成物品、不进入玩家背包**；仅改造体网络内部转化；玩家可能看到网络进度，并可通过 UC-17 向其出售医疗品。

**分支/异常**：
- **B1（背包满）**：物品掉落在店铺地面，可拾取；次日未拾取按原版掉落/查获规则处理。
- **B2（保存超期）**：超过 `aug.human.lifetimeDays`（建议 3 天）目标死亡，物品失效并提高风险。
- **B3（玩家丢弃/销毁）**：降低风险但失去转化材料；丢弃在店外可能触发世界事件【待定】。
- **B4（自主改造体缺医疗品）**：以顾客请求形式向玩家购买（UC-17），不生成人类物品。

**后置状态**：`humanItemCount`；风险计时；检查/损失；网络改造进度联动。

**验收标准**：
- AC1：玩家指派抓捕成功生成"人类"物品并占格；失败不生成。
- AC2：自主执行抓捕不生成玩家可持有物品（背包断言无新物品）。
- AC3：每夜保存风险判定可复现，被查获时走原版违禁品流程。
- AC4：超过保存期限物品失效，且与手术/转化流程正确互斥。

**调参/配置点**：`aug.human.grid=1x2`；`aug.human.decayRisk=0.05`；`aug.human.shelfRisk=0.10`；`aug.human.lifetimeDays=3`；罚金倍率。

**关联 UC**：UC-21、UC-23、UC-24。

### UC-23 植入物过夜转化

**涉及系统**："人类"物品 / 植入物 / 夜间改造槽 / 经费　　**适用玩家类型**：Z、A

**前置条件**：持有"人类"物品（UC-22）；持有对应改造体植入物；当晚改造槽空闲；未强制休眠。

**触发条件**：玩家在"人类"物品交互菜单选择"植入物过夜转化"，并选择消耗的植入物。

**主流程**：
1. 开销校验：植入物层级 ≥ 目标身份等级要求（建议：基础层可改低身份；高身份需伪装层以上【待定】）；改造槽 `nightSlots` 空闲。
2. 确认后占用改造槽，消耗植入物与"人类"物品，创建转化条目 `{startDay, quality, targetTier}`。
3. 夜间结算推进：所需夜数按身份/品质（建议低身份 1 夜、高身份 2 夜）；完成时生成 1 名HIDDEN 改造体，加入名册，触发次日报到/入网通知。

**分支/异常**：
- **B1（同晚已有手术）**：改造槽冲突，只能执行一个，另一个顺延；UI 明确提示。
- **B2（植入物品质过低）**：失败率提升（建议 20% 失败，人类物品损失）；失败记录日志。
- **B3（转化期间被检查）**：按进度风险判定，可能中断并损失（人类物品/植入物不返还）。
- **B4（F 类型 / 未掌控）**：F 无法执行转化（无改造体科技/网络），持有的人类物品只能出售/丢弃【待定 Q5】。

**后置状态**：人类物品/植入物消耗；改造槽占用；新HIDDEN 改造体；经费（完成时）；日志/日历。

**验收标准**：
- AC1：过夜转化消耗对应植入物与"人类"物品，完成时产出 1 名HIDDEN 改造体。
- AC2：改造槽每晚只能进行 1 项转化或手术，冲突时禁止并提示。
- AC3：层级不满足时禁止转化，物品与材料不扣除。
- AC4：完成日正确结算经费奖励（UC-29）。

**调参/配置点**：`aug.convert.nightsByTier=[1,2]`；失败率；改造槽数量 `aug.night.slots=1`；层级要求表；`aug.convert.checkRisk=0.03`。

**关联 UC**：UC-12、UC-22、UC-24、UC-29。

### UC-24 夜间手术改造（医疗品 / 目标防护 / 纳米疫苗 / 手术工具）

**涉及系统**："人类"物品 / 夜间外出机会 / 医疗品 / 手术工具 / 经费　　**适用玩家类型**：Z、A

**前置条件**：持有"人类"物品；持有带"医疗品"标签的物品，或原版 200 信用点手术工具；当晚夜间外出未使用；改造槽空闲。

**触发条件**：玩家在"人类"物品交互菜单选择"夜间手术改造"，打开手术面板。

**主流程**：
1. 手术面板显示：目标身份等级（下层/中层/上层）、防护等级、当前进度、可选医疗品/工具、预计耗时。
2. 校验并消耗：`nightOutUsed=false` → 置 `true`（消耗夜间外出机会）；占用改造槽；二者任一不满足则拒绝。
3. 医疗品路径：`progress = 25 × (medicalValue/100) × (1 + 科技加成) × (1 − 防护系数)`【建议公式】，消耗所选医疗品。
4. 防护与纳米疫苗：目标防护每级 −10% 进度；`alertness ≥50` 时，上层目标有 `nanoVaccineChance=(alertness−50)×1%` 概率已接种纳米疫苗 → 总需求进度 ×2.5、单夜进度 ×0.5【待定】。
5. 手术工具特例：使用 200 信用点手术工具时**不消耗医疗品**（或按配置叠加），单夜进度 +100%~150%，工具按配置 50% 保留【待定】。
6. 进度累计到 100 → 完成改造，生成 HIDDEN 改造体并进入"接纳"流程（UC-29）；未完成则保留进度条目，次日继续（再次占用夜出机会/医疗品）。
7. 手术期间风险：按 `alertness` 与目标防护判定被检查/目击事件（建议 5%~15%/夜【待定】），失败损失进度。

**分支/异常**：
- **B1（医疗品价值不足）**：单夜进度 <10%，面板提示更换高价值医疗品；不强制开始。
- **B2（目标已接种纳米疫苗）**：显示"目标已接种，耗时显著增加"，玩家可放弃（保留"人类"物品，医疗品不返还）。
- **B3（手术中断：被检查/冲突）**：进度保留、人类物品保留；当晚夜出机会已消耗；次日可继续。
- **B4（目标死亡/保存超期）**：物品销毁，进度清零，声望不变，不结算经费。

**后置状态**：手术进度条目；医疗品/工具消耗；夜间外出机会消耗；完成后改造体 + 经费待结算；日志/日历。

**验收标准**：
- AC1：手术消耗夜间外出机会，当日不能再选择夜间外出（UC-04）。
- AC2：进度公式对医疗品价值/防护等级/警觉度/纳米疫苗/工具五个变量分别敏感（单变量测试）。

## 10. 治安部追查与警觉度

### UC-26 逃逸进度与警觉度激活

**涉及系统**：治安部 / 逃逸进度 / 警觉度　　**适用玩家类型**：Z、A、F

**前置条件**：玩家为 Z/A/F；每日结算；警觉度状态可写。

**触发条件**：日初结算；治安部调查事件；改造体行动结算。

**主流程**：
1. **Z**：日初 `escapeProgress += 3`（固定日增长【待定】）；改造体行动额外 +1~+5/次（触发即加）。未满 100 时 `alertness=0`、`alertnessActive=false`，所有警觉效果按 0 计算；UI 显示"逃逸被发现进度 X/100"。
2. **Z 满 100**：`alertnessActive=true`、`alertness=20`（与 A/F 对齐【待定】）；触发"治安部开始注意"提示与日历事件；此后逃逸进度隐藏/不再增长。
3. **A/F**：开局（类型初始化后）`alertnessActive=true`、`alertness=20`（权威口径）；之后按行动累积。
4. 已激活后：每日是否自然增长建议 +1【待定】；无行动日仍会缓慢上升，避免玩家挂机归零。
5. 激活/数值变化写入存档与日历；治安部面板显示来源与最近事件。

**分支/异常**：
- **B1（逃逸满前击杀/降警觉）**：不影响逃逸进度（逃逸是固定记录）；警觉未激活时降警觉无效。
- **B2（满 100 当日恰逢电量归零）**：激活立即生效，效果从次日起按新数值计算（避免空窗）。
- **B3（旧存档迁移）**：无字段时补默认：Z → 0/未激活；A/F → 20/已激活（UC-30）。
- **B4（背叛）**：警觉保持激活并继续累积；改造体敌对行为另按 UC-08 处理。

**后置状态**：`escapeProgress`；`alertness`/`alertnessActive`；UI/日历；日志。

**验收标准**：
- AC1：Z 未满 100 前 `alertnessActive=false`，警觉派生效果为 0；满 100 后激活且初始值 = 配置值。
- AC2：A/F 从任务线转入或原版开局后 `alertnessActive=true`，初始警觉度 = 20。
- AC3：未激活前击杀不产生警觉度变化（或记录为 0），不出现负值。
- AC4：旧存档迁移后字段完整、不崩溃。

**调参/配置点**：`aug.escape.daily=3`；`aug.escape.perAction=1~5`；`aug.alert.initialOnActivate=20`；`aug.alert.dailyDrift=1`。

**关联 UC**：UC-02、UC-27、UC-28、UC-30。

### UC-27 警觉度效果模型（防护率 / 鉴别率 / 报警率 / 手术难度）

**涉及系统**：治安部 / 警觉度 / 检查 / 手术 / 经费　　**适用玩家类型**：Z、A、F

**前置条件**：`alertnessActive=true`；`alertness` 在 0~100 之间。

**触发条件**：每日刷新；顾客生成；检查/交易判定；手术结算；经费结算。

**主流程**：
1. 派生系数（建议初值，全部可配）：

| 系数 | 公式（建议） | 0 → 100 效果 |
| --- | --- | --- |
| 防护率（NPC 拥有防护概率） | 5% + alertness × 0.4% | 5% → 45% |
| 鉴别率（识别植入物概率） | alertness × 0.6% | 0% → 60% |
| 报警率 | **恒 100%**（基线"被发现必报警"） | 100% |
| 手术难度 | 1 + alertness/100 | ×1.0 → ×2.0 |
| 纳米疫苗率 | max(0, (alertness−50) × 1%) | 0% → 50% |

2. 应用到：顾客生成（防护 NPC 比例）、检查（鉴别率）、销售暴露（UC-15）、手术进度（UC-24）、经费修正（UC-29）。
3. 警觉度来源：报警 +5、暴露 +3、击杀改造体 −3（前 3 次）/ −1（之后，UC-28）、世界事件压制、日漂移 +1；钳制 0~100。
4. 治安部面板显示：警觉度条、当前系数、最近 5 条来源；高警觉日（≥80）在日历标红。
5. 数值变化后当日立即刷新缓存，不重启生效。

**分支/异常**：
- **B1（警觉 100）**：鉴别率 60%、防护 45%、疫苗率 50%、手术难度 ×2.0；仍可游戏但销售风险极高。
- **B2（未激活/负数）**：Z 未激活时所有系数按 0 效果计算（防护 0%、鉴别 0%、疫苗 0%、手术难度 1.0）；已激活但数值为 0 时按表取最小值（防护 5%）；负数钳制 0。
- **B3（击杀降到 0）**：效果归零，击杀奖励链照常（UC-28）。
- **B4（世界事件压制）**：显示"压制中（剩余 N 天）"，结束后反弹（UC-21）。

**后置状态**：派生系数缓存；UI；后续判定使用新系数；日志。

**验收标准**：
- AC1：警觉 0/50/100 三档的防护率、鉴别率、疫苗率、手术难度与表格一致（数值测试）。
- AC2：被发现时 100% 报警，无随机跳过。
- AC3：警觉度变化后当日判定立即使用新值（无需次日/重启）。
- AC4：系数与来源可在治安部面板/调试面板查看与复现。

**调参/配置点**：各系数斜率；报警率固定 1.0；`aug.alert.nanoThreshold=50`；日漂移 +1；压制系数。

**关联 UC**：UC-15、UC-24、UC-26、UC-28、UC-29。

### UC-28 击杀改造体降低警觉度与反刷分

**涉及系统**：击杀 / 警觉度 / 声望　　**适用玩家类型**：Z、A、F、U

**前置条件**：玩家遇到可击杀改造体（原版战斗/外出袭击/潜入）；`alertnessActive=true`。

**触发条件**：改造体被击杀（生命归零/处决）。

**主流程**：
1. 走原版击杀奖励：信用点 = `100 + (当前天数 − 改造体引入日)` 钳制 **100–250**；治安部声望 **+8**，革命军/黑市/下层区各 **+2**；改造体声望**不变**（锁定 0 变化，UC-08）。
2. 警觉度降低：每次 −3；**每日前 3 次全额 −3，第 4 次起每次 −1**（权威口径）；钳制 ≥0。
3. 计数器 `killAlertCountToday` 日初重置；面板/日志显示"今日降警觉次数 3/3 已用"。
4. 击杀记录（对象、地点、警觉变化、声望变化=0）；日历可见。
5. 若因此 `augCount` 归零且已背叛 → 触发灭绝奖励（UC-08）。
6. 击杀改造体不触发背叛锁定；也不减少改造体声望（与 UC-08 一致）。

**分支/异常**：
- **B1（击杀普通 NPC/治安员）**：不降警觉，走原版犯罪流程；改造体声望不变。
- **B2（警觉未激活：Z 未满逃逸）**：降警觉无效（保持 0），不记录"待补"（避免激活后白送减益）。
- **B3（同日第 4+ 次击杀）**：获得原版奖励，但仅 −1 警觉，UI 提示递减。
- **B4（击杀已掌控改造体）**：声望不降（基线），但失去该改造体，调度容量与指令结果减少。

**后置状态**：`alertness` 降低；`killAlertCountToday`；击杀记录；改造体数量；灭绝判定。

**验收标准**：
- AC1：单次击杀改造体后警觉 −3，且改造体声望不变。
- AC2：同日前 3 次每次 −3，第 4 次起每次 −1，无法无限刷。
- AC3：击杀普通 NPC 不减少警觉度。
- AC4：声望锁定 -100 时击杀仍按原版结算，且声望保持 -100。

**调参/配置点**：`aug.alert.killReduction=3`；`aug.alert.killFullCount=3`；`aug.alert.killDiminished=1`；按日重置。

**关联 UC**：UC-08、UC-26、UC-27。

## 11. 改造经费与存档

### UC-29 改造成功经费奖励（按身份等级）

**涉及系统**：改造完成 / 经费 / 身份等级 / 警觉度　　**适用玩家类型**：Z、A

**前置条件**：一次改造成功（UC-23 植入物过夜转化完成，或 UC-24 手术改造完成）；目标身份等级已知；不是改造体自主转化。

**触发条件**：改造进度达到 100% 且玩家接纳该改造体（默认自动接纳，可在改造体面板拒绝）。

**主流程**：
1. 读取身份等级基础经费（权威口径）：**下层 60 / 中层 150 / 上层 400** 信用点。
2. 修正：`reward = base × (1 − 0.02 × protectionLevel) × (1 − alertness/250) × (1 + 科技加成)`，最低 10；警觉度/防护越高经费越低（基线"受警觉度和防护等级约束"）。
3. 直接入账玩家信用点，弹出"改造经费 +X"提示；写入日志与日历。
4. 同一目标只结算一次；失败/死亡/拒绝接纳不结算。
5. 与植入物销售收入独立，不与声望值挂钩；改造体自主执行（UC-21/22）永不发放。

**分支/异常**：
- **B1（玩家拒绝接纳）**：改造体转为 AUTONOMOUS，不发经费；后续可按 UC-09/UC-20 规则处理。
- **B2（高警觉/高防护压到下限）**：仍发放最低 10，提示"风险过高，经费被压低"。
- **B3（主目标与关联 NPC 同时改造）**：只有主目标结算，关联 NPC（UC-16）不结算【待定 Q9】。
- **B4（销售感染转化）**：由植入物销售感染、次日报到并被玩家接纳的 NPC **正常发放经费**（符合"成功改造一名 NPC"定义）；未接纳/自主转化不发。若担心刷经费，用每日上限或递减控制，而不是取消。

**后置状态**：信用点增加；改造体接纳状态；日历/日志；目标状态。

**验收标准**：
- AC1：下层/中层/上层改造成功分别发放 60/150/400（未受修正影响时）。
- AC2：同一目标不重复发放；读档回退后不重复入账。
- AC3：高警觉/高防护下奖励按公式降低，且有最低 10 下限。
- AC4：自主转化、失败、目标死亡、玩家拒绝接纳均不发放。
- AC5：植入物销售感染、次日报到并被接纳的 NPC 正常发放；未接纳/自主转化不发。

**调参/配置点**：`aug.funding.lower=60`；`aug.funding.mid=150`；`aug.funding.upper=400`；`protectionPenalty=0.02`；`alertnessDivisor=250`；最低 10；科技加成。

**关联 UC**：UC-16、UC-23、UC-24、UC-27。

### UC-30 存档 / 跨天持久化与日历可见性

**涉及系统**：存档 / 日历 / 跨天结算　　**适用玩家类型**：Z、A、F、U

**前置条件**：任意阶段；原版存档系统可用；Mod 数据可读写。

**触发条件**：日终结算完成；重要状态变化（售出植入物、改造完成、背叛、击杀、阈值变化）；玩家手动存档/读档。

**主流程**：
1. 持久化字段全集（`aug.*` 命名空间）：`playerType`、`bodyEnergy/max`、`augReputation/repLocked`、`alertness/active`、`escapeProgress`、`augCount` 与名册（状态 HIDDEN/TASKED/AUTONOMOUS/EXPOSED/DEAD、身份、防护、任务、冷却）、`assignments`、`humanItems`、`techState`、`researchPoints`、转化/手术进度、`soldImplantQueue`、`calendarEntries`、`worldEvents`、`saveVersion`。
2. 写入时机：日终结算完成后写主存档；关键状态变化立即写（防止回档丢奖励）。
3. 读档：校验 `saveVersion`；缺失字段按迁移表补默认；类型与字段矛盾（如 F 有电量）以类型为准修正并记录警告。
4. 跨天：按附录 B.4 顺序结算后写日历条目。日历显示：改造体行动（≥40，只读）、报到事件、感染/转化/手术倒计时、夜间指令结果、世界事件、强制休眠、警觉变化。
5. 可见性受声望阈值控制：<40 时未掌控（AUTONOMOUS）改造体行动隐藏或显示模糊条目【待定】；≥40 显示具体行动但不可编辑。
6. 读/写失败：保留原版存档；Mod 数据降级为内存态并提示玩家，不阻塞游戏。

**分支/异常**：
- **B1（旧版存档缺少 Mod 字段）**：迁移补默认（U 类型补声望 0；Z 补电量/逃逸；A/F 补警觉 20），不崩溃。
- **B2（同一日重复读档）**：以 `lastResolvedDay` 去重，不重复发奖励/扣电/感染判定。
- **B3（"人类"物品已过期未结算）**：读档时按当前日补算失效/风险，并写日志。
- **B4（云存档/多人冲突）**：沿用原版规则，Mod 不做合并；冲突时提示以哪份为准。

**后置状态**：存档完整；日历可见；跨天状态一致；迁移/失败后游戏可继续。

**验收标准**：
- AC1：保存→读取后所有 `aug.*` 字段逐项一致（含名册状态、任务、进度）。
- AC2：同一日重复读档不重复发奖/扣电/感染判定。
- AC3：声望 ≥40 时日历显示 AUTONOMOUS 改造体行动且不可编辑；<40 时隐藏/模糊。
- AC4：v0.2 旧存档迁移后不崩溃且补默认值。

**调参/配置点**：`aug.save.version=1`；日历条目上限；自动存档时机；模糊条目开关 `aug.calendar.fuzzyUnder40`。

**关联 UC**：UC-02、UC-09、UC-16、UC-19、UC-21、UC-25、UC-26。

## 附录 B　跨用例状态机与全局规则

### B.1 日循环状态机

```
DAY_START（日初：自然耗电 −5 / 声望阈值生效 / ≥20 额外顾客生成 / 日历刷新）
  → SHOP_OPEN（营业：顾客、交易、植入物销售、暴露与报警）
  → SHOP_CLOSE（闭店：顾客清场）
  → NIGHT_PLAN（夜间：选择外出（−5）/ 分配指令 / 转化 / 手术（消耗外出机会））
  → NIGHT_RESOLVE（夜间结算：指令结果 → 感染判定 → 报到排期 → 保存风险）
  → DAY_END（日终：电费支付判定（付且未外出额外 +5）/ 警觉日漂移 / 归零休眠判定 / 存档）
  → 次日 DAY_START
```

- 夜间外出发生在 SHOP_CLOSE 之后，**不影响当日营业、不会错过客人**（权威口径）；只影响电量与当晚可执行的其他夜间行动。
- 日终顺序固定，任何结算不得跨阶段提前执行（见 B.4）。

### B.2 玩家类型状态机

```
U（原版开局 / 未走任务线）
 ├─ 声望 ≥30 选择「接受改造」→ A（创建电量池、警觉 20、双轨科技树）
 ├─ 声望 ≥30 选择「作为朋友加入」→ F（无电量池、警觉 20、声望上限 99、无科技树）
 └─ 不参与 → 保持 U（原版流程）

Z（开局特质）── 固定，不走 A/F 迁移；全局掌控按声望 100 生效
A/F ── 任务线「背叛」→ 声望锁定 -100（不可逆）；F 仍无电量池
```

- Z 开局**全部改造体视为已掌控**；A 在声望 <100 时存在 AUTONOMOUS 改造体，达 100 全部收回；F 始终全部 AUTONOMOUS（无掌握能力）。
- 是否允许 F→A 后悔转换：**未定**（附录 C-Q3），默认不允许。

### B.3 改造体状态机（统一术语）

| 状态 | 含义 | 可执行 |
| --- | --- | --- |
| **HIDDEN** | 隐藏身份生活，可作顾客到店 | 购买/捐赠/请求/被指出破绽；计入 ≥20 名额 |
| **TASKED** | 当晚执行夜间指令 | 不参与顾客生成、不计入 ≥20 名额 |
| **AUTONOMOUS** | 失控（AUTONOMOUS）/未被掌控，自主行动 | 日历可见（≥40）、自主抓捕不交付、可能敌对 |
| **EXPOSED** | 伪装被识破（临时状态） | 触发报警/检查，之后转 HIDDEN 或 DEAD |
| **DEAD** | 死亡 | 移除名册、释放调度容量、不降声望 |

```
HIDDEN --分配指令--> TASKED --结算--> HIDDEN / DEAD /（受伤：HIDDEN 冷却）
HIDDEN --被识破--> EXPOSED --报警--> 检查/逮捕/释放 --> HIDDEN / DEAD
AUTONOMOUS --声望 100（Z/A）--> HIDDEN（收回掌控）
HIDDEN/AUTONOMOUS --击杀--> DEAD（声望不变）
```

### B.4 跨天结算顺序（唯一权威顺序）

1. 日初：自然耗电 −5 → 声望阈值评估 → 额外顾客名额（UC-19）→ 报到队列（UC-16）→ 日历刷新。
2. 营业：顾客生成/交易/销售/暴露（UC-15）→ 售出队列累积。
3. 闭店：外出决策（UC-04）→ 夜间指令分配（UC-20）→ 转化/手术（UC-23/24）。
4. 夜间结算：指令结果与警觉增量（UC-21）→ 感染判定（UC-16）→ 保存风险（UC-22）→ 转化进度（UC-23）→ 手术进度（UC-24）。
5. 日终：电费支付与"付且未外出额外 +5"（UC-03）→ 警觉日漂移（UC-26）→ 归零休眠判定（UC-06，**次日生效**）→ 灭绝/阈值事件 → 写日历 → 存档（UC-30）。

### B.5 全局钳制与上限（防止刷取/死锁）

| 规则 | 值/行为 |
| --- | --- |
| 电量 | 0~100；付电费 +5；付且未外出额外 +5；夜出 −5；次日休眠恢复 1；连续 3 天触发休眠 → 强制 10 |
| 声望 | −100~100；F/U 上限 99；背叛锁定后所有获取失败 |

| 改造槽 | 默认 1/夜（转化与手术互斥） |
| 指令容量 | 默认 3（科技可升） |
| 抽取/随机 | 固定种子 + 判定点日志，可复现 |
| 防死锁 | 原版营业永不禁用；休眠次日恢复；充值/付电费可当日解除（默认 true） |
