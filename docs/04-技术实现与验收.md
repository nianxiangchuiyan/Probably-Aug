## 1. 技术结论

### 1.1 是 Mono，不是 IL2CPP

| 证据 | 说明 |
|---|---|
| `Probably Stolen_Data\Managed\Assembly-CSharp.dll` | 托管程序集存在 |
| `Probably Stolen_Data\Managed\0Harmony.dll`（2.4.2） | 游戏自带 Harmony |
| 游戏根目录 `MonoBleedingEdge\` | Mono 运行时 |
| 无 `il2cpp_data` | 非 IL2CPP |
| `Assembly-CSharp.dll` 类型/方法可读 | 未混淆，可反编译 |

**结论**：无需 Il2CppInterop/IL2CPP hook；Harmony patch 可直接用。

### 1.2 不需要 MelonLoader / BepInEx

游戏**自带 Mod 加载器**：

- `ModLoader` 单例：`LoadAllMods()`、`LoadModFromFolder()`、`LoadModDll()`、`ParseManifest()`、`ValidatePrerequisites()`、`ResolveModDependency()`、`LoadModAssets()`、`LoadTextures()`、`LoadLocalization()`、`SetModEnabled()`、`ReorderMods()`、`LogAudit()`。
- Mod 目录：`Mods\<ModID>\manifest.xml` + DLL，游戏内 Mod 页启用。
- `IMod` 入口：`Init(ModManifest)`、`OnEnable()`、`OnDisable()`。
- `LoadedMod`：`Instance`、`Manifest`、`Assembly`、**`HarmonyInstance`**、`FolderPath`、`DllPath`、`Source`、`WorkshopId`、`TrustState`、`Textures/Sprites/Sounds/Localization`。
- 能力声明：`ModCapability` = `files / network / process / dynamic-code / native / reflection-external / steam / steam-auth`；`ModScanner`/`ModTrust` 会扫描未声明能力。**manifest 必须声明最小能力集**。

> v0.2 的"MelonLoader（IL2CPP）"假设作废。MelonLoader 最多是可选第三方加载器，不是前置。

## 3. 原版机制与复用点

### 3.1 改造体（Aug）系统

| 符号/机制 | 事实 | 复用方式 |
|---|---|---|
| `StoreClient.isAug/augTier/isAugScanned/augIdleTell` | 顾客即改造体，有等级/扫描/破绽 | 直接判定"改造体顾客" |
| `AugHelper.RollAugTier`、`MakeDisguisedAug`、`SetRandomAugFaction` | 改造体等级/伪装/派系 | 伪装型植入物复用 |
| `AugHelper.OnGoodKill`、`OnAugLeftAlive` | 击杀/放走后果 | 击杀奖励/存在度 |
| `augPresence` | 初始 15；放走 +10、击杀 −25；满 100 结束本局 | 可作为"改造体威胁/关注度"反向指标 |
| `AUG_INTRODUCED_DAY` | 普通开局第 12 天引入 | ZERO 需抑制随机引入 |
| `AUG_DISGUISE_TYPES`、`AUG_DISGUISE_CHANCE`、`AUG_SHAKE_*`、`AUG_STILL_CHANCE` | 伪装/破绽参数 | "指出破绽"判定 |
| `AugScanner` | 扫描仪价值 200，耗 25 能量，100% 准确 | 识别系统复用 |
| `AUG_MENACE` | 改造体危机特质：花费 1 点、第 1 天、存在度满 100 结束 | 与零号互斥 |
| `AUG_ALL_CLEAR_DAYS/PERMIT_DAYS` | 引入 50 天后存在度归 0 + 许可证 25 天 → 清除完毕 | 长期经营需处理 |

**设计影响**：
- Mod 的"改造体"不是新 NPC 类型，而是**原版改造体 + 玩家控制网络**；
- ZERO 需接管/抑制随机到访（`AugHelper.RollAugTier` / `IsInTierHoldWindow`），同时不能破坏原版终局；
- "改造体数量/灭绝"可参考 `augPresence`，但用户设计的"数量"是独立变量，建议两者分开、必要时同步。

### 3.2 违禁品/盘查/犯罪

| 符号 | 用途 |
|---|---|
| `ContrabandHelper.InitContrabandItem(item[,level])` | 标记违禁品；等级 LOW/MID/HIGH/CRITICAL |
| `ContrabandHelper.StartInspection(personality, fromShowcase)` | 盘查 |
| `ContrabandHelper.GetSeizedItems`、`GetFineAmount`、`GetBribeAmount` | 没收/罚款/贿赂 |
| `ContrabandHelper.IsConcealedFromInspection`、`IsSmugglerBay` | 藏匿判定 |
| `StolenHelper` | 赃物热度/被查概率 |
| `SecData.CommitCrime(id,amount)`、`CheckSoldContraband`、`SendOfficer`、`GetProjectedSentence` | 犯罪/证据/判决 |

**设计影响**：
- 植入物与"人类"直接 `InitContrabandItem(..., CRITICAL)`；
- "被发现必报警"可复用盘查链，但需决定是否额外记罪/罚款；
- **展示柜是警报器**：赃物/违禁品放展示柜每天掷骰触发盘查；光学迷彩 0 信用点摆放必须绕开 `SecurityCheckDisplayCase`，改用柜台/隐藏区/暗格；
- 原版盘查规则：低级警告、中级/赃物没收、高级没收+罚款、高危被捕。

### 3.3 声望

| 事实 | 影响 |
|---|---|
| 原版 5 常规派系：下层区/上层区/治安部/黑市/革命军；卡特尔隐藏 | "第五派系"实际是第六个 |
| `StoreReputation` 读写按固定派系写死（Sec/Rev/BM/UL/LL/Cartel） | build 26525552 仍**无 `AddFaction`/`CreateFaction` 官方方法**；需扩展 |
| 工坊已有"额外派系声望"Mod；卡特尔为隐藏派系先例 | 说明**可以**扩展原版派系栏，但走 Harmony/反射，不是纯官方 API |
| 工坊 `3830995342`（深空罗德岛）本地实测 | 用 Harmony/反射操作 `List<StoreReputation>`：`Add`/`Insert` 新 `StoreReputation`、`ModReputationRaw`；manifest `<Capabilities />` 为空，派系栏可显示 |
| 工坊 `3833223505`（声望面板滚动修复）本地实测 | Harmony patch `ReputationUIManager`，派系多时可横向滚动/分页；manifest `<Capabilities />` 为空；说明派系栏可容纳更多派系 |
| 2026-11-09 更新 | 游戏把"通过反射访问内部实现""运行时加载/生成代码"等能力列入淘汰名单；2026-12-10 起可能拒绝带这些声明的 Mod。**基础 Mod 应只用官方 API；派系扩展需评估后续兼容** |
| 数值范围 −200~200，22 级 | 用户设计 −100~100 是另一套量纲 |
| 下层区 ≥20：每天额外 1 名随机顾客 | 与"改造体声望 ≥20 加顾客"结构相同，复用 `StoreClientManager.AddClient` |
| 治安部 ≥100 VIP / ≥60 值得信赖 / ≤−20 重点盯防 / ≤−60 头号通缉 | 与"警觉度"是两套压力，不要合并 |

**结论（最大架构风险）**：派系栏扩展已被工坊 Mod 证实可行：`3830995342` 通过 Harmony/反射把新 `StoreReputation` 插入 `List<StoreReputation>`，`3833223505` 用 Harmony patch `ReputationUIManager` 做横向滚动。两者 manifest 的 `<Capabilities />` 为空，但 **2026-11-09 游戏更新已把反射/运行时生成代码列入淘汰名单，2026-12-10 起可能拒绝带这些声明的 Mod**。因此分两层：
- **基础 Mod（当前）**：只用官方 `ModHook`/`ModHelper`/`ModData`，不引入 Harmony/反射，`Capabilities` 为空；
- **派系扩展（第二阶段）**：参考 `3830995342` 的实现，但必须评估能力声明/未来兼容；失败回退 `ModData` + 自建面板（PaperUI/ModConfigWindow）。

## 6. 数据与存档

### 6.1 官方方案

- 配置：`ModConfig.Define(key, defaultValue, section, label, tooltip, requiresRestart)` + `Load/Save`。
- 运行时状态：`ModHelper.SetModData*` / `GetModData*`（建议按 `RunId` 分区）；大文本用 `WriteModDataFileText`。
- 读档：`ModHook.OnGameLoaded*` 恢复；`LoadGameEvent` 可读 Day/RunId/Credit 等。
- 不要写进原版存档结构；不要依赖 `ES3` 内部格式。

### 6.2 需要持久化

- 玩家身份、声望、电量、逃逸进度、警觉度、犯罪值；
- 科技树节点、科研点/冷却；
- 网络：`npcId`、状态、tier、protection、convertedDay、cooldown、预算；
- `PendingInfection` 队列；
- "人类"物品实例；
- 世界事件冷却/队列；
- `augSaveVersion` 与迁移标记。

### 6.3 读档校验

1. 版本迁移；
2. 身份/特质互斥坏档修复；
3. 网络引用完整性（NPC 不存在则移除）；
4. 缺失字段默认值 + 日志，不阻断读档。
